# 社区业务 V2 增强版产品原型文档

## 1. 文档说明

### 1.1 文档定位

本文档基于原《社区业务一期 MVP 产品原型文档》进行扩展，补充社区平台从基础内容社区升级为完整兴趣社区平台所需的增强功能。

本版本新增能力包括：

```text
1. 内容标签
2. 圈子模块
3. 话题模块
4. 定时发布
5. 内容筛选
6. 分享
7. 转发
8. 搜索与推荐体系
9. 积分与成长体系
10. 活动与运营体系
11. 后台圈子、话题、标签、推荐、活动管理
```

### 1.2 产品升级目标

原一期 MVP 解决的是：

```text
用户能注册登录
用户能发布内容
用户能浏览内容
用户能评论互动
平台能审核治理
后台能管理数据
```

V2 增强版要进一步解决：

```text
内容如何被分类
用户如何围绕兴趣聚集
内容如何被搜索和推荐
优质内容如何沉淀
用户如何被激励持续活跃
运营如何制造社区活跃度
```

### 1.3 最新完整功能模块

```text
社区系统
├── 用户体系
├── 内容发布体系
├── 内容浏览体系
├── 内容标签体系
├── 圈子体系
├── 话题体系
├── 评论互动体系
├── 关系体系
├── 通知体系
├── 审核与治理体系
├── 搜索与推荐体系
├── 积分与成长体系
├── 活动与运营体系
├── 后台管理体系
└── 数据统计体系
```

# 2. 内容标签模块

## 2.1 功能定位

内容标签用于对帖子进行结构化分类，方便后续实现内容检索、推荐、聚合和运营管理。

标签可以理解为内容的关键词，例如：

```text
Go语言
React
后端开发
AI工具
项目实战
数据库
职场经验
学习笔记
```

## 2.2 业务目标

```text
1. 创作者发布内容时必须至少选择一个标签。
2. 用户可以通过标签聚合查看相关内容。
3. 推荐系统可以基于标签理解用户兴趣。
4. 管理员可以在后台新增、编辑、禁用标签。
5. 后续搜索、推荐、话题、圈子都可以复用标签能力。
```

## 2.3 前台功能

### 2.3.1 发布内容选择标签

在发布帖子页新增标签选择区域。

页面结构：

```text
发布帖子页
------------------------------------------------
标题输入框

正文输入框

图片上传区

内容标签：
[选择标签输入框]
已选标签：
[Go语言 x] [项目实战 x]

[保存草稿] [定时发布] [发布]
------------------------------------------------
```

交互说明：

| 操作        | 效果               |
| --------- | ---------------- |
| 点击标签输入框   | 展开标签选择下拉框        |
| 输入关键词     | 搜索匹配标签           |
| 点击标签      | 添加到已选标签          |
| 点击已选标签的 x | 移除该标签            |
| 发布时未选择标签  | 提示“请至少选择一个内容标签”  |
| 最多选择标签数量  | 建议最多 5 个         |
| 标签不存在     | 普通用户不可创建，管理员后台创建 |

### 2.3.2 帖子卡片展示标签

首页、关注流、热门榜单、圈子内容流中，帖子卡片增加标签展示。

```text
帖子标题
帖子摘要

[Go语言] [项目实战] [后端开发]

点赞 128  评论 32  收藏 88
```

交互说明：

| 操作   | 效果                 |
| ---- | ------------------ |
| 点击标签 | 跳转标签聚合页            |
| 标签过多 | 最多展示 3 个，其余用“+2”表示 |

### 2.3.3 标签聚合页

用户点击某个标签后，进入标签聚合页。

页面结构：

```text
标签聚合页
------------------------------------------------

相关内容数量：128

筛选：
[最新] [热门]
[发布时间] [内容类型]

帖子列表
------------------------------------------------
```

交互说明：

| 操作     | 效果      |
| ------ | ------- |
| 点击最新   | 按发布时间倒序 |
| 点击热门   | 按热度分倒序  |
| 选择发布时间 | 按时间范围筛选 |
| 点击帖子   | 进入帖子详情  |

# 3. 圈子模块

## 3.1 功能定位

圈子是围绕兴趣、主题、身份或场景形成的社区空间，类似于“兴趣小组”或“群组社区”。

圈子与群聊类似，但更偏内容沉淀：

```text
群聊：实时交流为主
圈子：内容发布、沉淀、治理、讨论为主
```

示例圈子：

```text
Go 后端开发圈
React 前端圈
AI 工具分享圈
个人项目实战圈
数据平台研发圈
```

## 3.2 业务目标

```text
1. 用户可以创建或加入兴趣圈子。
2. 圈子有独立首页、公告、规则、成员和内容流。
3. 圈子内支持帖子置顶、精华内容沉淀。
4. 圈子管理员可以管理成员、禁言、踢人。
5. 平台管理员可以在后台管理所有圈子。
```

## 3.3 圈子角色

| 角色    | 权限                        |
| ----- | ------------------------- |
| 圈主    | 圈子最高权限，管理圈子信息、成员、版主、公告、规则 |
| 版主    | 协助管理内容和成员                 |
| 审核员   | 负责内容审核                    |
| 普通成员  | 浏览、发帖、评论                  |
| 被禁言成员 | 可浏览，不可发帖评论                |
| 非成员   | 可浏览公开圈子内容，是否能发帖取决于圈子设置    |

## 3.4 创建圈子

### 页面入口

| 入口    | 说明            |
| ----- | ------------- |
| 圈子列表页 | 点击“创建圈子”      |
| 我的主页  | 可增加“我创建的圈子”入口 |
| 后台管理  | 管理员可创建官方圈子    |

### 创建圈子页面

```text
创建圈子
------------------------------------------------
圈子头像上传

圈子名称输入框
圈子简介输入框
圈子分类选择
圈子标签选择

加入方式：
○ 直接加入
○ 需要审批

发帖权限：
○ 所有成员可发帖
○ 仅管理员和版主可发帖

圈子规则输入框

[取消] [创建圈子]
------------------------------------------------
```

### 交互说明

| 操作     | 效果            |
| ------ | ------------- |
| 输入圈子名称 | 校验是否重复        |
| 上传圈子头像 | 上传成功后展示预览     |
| 选择加入方式 | 决定用户加入时是否需要审批 |
| 点击创建   | 创建圈子，当前用户成为圈主 |
| 圈子名称为空 | 提示“请输入圈子名称”   |
| 圈子简介为空 | 提示“请输入圈子简介”   |
| 创建成功   | 跳转圈子首页        |

## 3.5 加入圈子

### 直接加入

```text
用户进入圈子首页
  ↓
点击加入圈子
  ↓
创建成员关系
  ↓
按钮变为“已加入”
```

### 审批加入

```text
用户进入圈子首页
  ↓
点击申请加入
  ↓
填写申请理由
  ↓
提交申请
  ↓
等待圈主或版主审批
```

申请弹窗：

```text
申请加入圈子
--------------------------------
申请理由：
[请输入你想加入圈子的原因]

[取消] [提交申请]
```

## 3.7 圈子内容发布

用户在圈子内发布帖子时，帖子需要绑定圈子。

新增字段：

```text
post.circleId
```

发帖规则：

| 场景        | 说明        |
| --------- | --------- |
| 用户未加入圈子   | 不允许在该圈子发帖 |
| 用户被圈子禁言   | 不允许发帖、评论  |
| 圈子仅管理员可发帖 | 普通成员不可发帖  |
| 内容命中敏感词   | 按审核规则处理   |

# 4. 话题模块

## 4.1 功能定位

话题用于聚合短期或长期讨论内容，通常以 `#话题名#` 的方式展示。

圈子偏社区空间，话题偏内容聚合。

示例：

```text
#本周学习计划#
#我的个人项目#
#AI 编程助手实践#
#React 组件设计#
#Go 后端工程化#
```

## 4.2 业务目标

```text
1. 用户发布帖子时可以选择或关联话题。
2. 用户可以进入话题页查看相关内容。
3. 管理员可以在后台创建和管理话题。
4. 运营可以创建官方话题活动。
5. 推荐系统可以根据用户参与话题理解兴趣。
```

## 4.3 前台话题展示

帖子卡片中展示话题：

```text
帖子标题
#AI编程助手实践# #个人项目实战#
帖子摘要
```

点击话题进入话题详情页。

## 4.4 发布内容选择话题

发布页新增话题选择区域：

```text
关联话题：
[搜索或选择话题]

已选话题：
[#AI编程助手实践 x] [#个人项目实战 x]
```

规则：

| 规则   | 说明               |
| ---- | ---------------- |
| 是否必选 | V2 建议非必选         |
| 最多选择 | 最多 3 个话题         |
| 创建话题 | 普通用户是否可创建由后台配置决定 |
| 官方话题 | 官方创建的话题优先展示      |

## 4.5 话题详情页

页面结构：

```text
话题详情页
------------------------------------------------
# AI 编程助手实践

话题简介：
分享 AI 编程助手在真实项目中的使用经验。

内容数量：560

[参与话题]

筛选：
[最新] [热门] [精华]

帖子列表
------------------------------------------------
```

交互说明：

| 操作     | 效果           |
| ------ | ------------ |
| 点击参与话题 | 发布帖子时自动带入该话题 |
| 点击最新   | 按发布时间排序      |
| 点击热门   | 按热度排序        |
| 点击精华   | 只看精华内容       |

## 4.6 后台话题管理

后台新增“话题管理”菜单。

页面结构：

# 5. 定时发布功能

## 5.1 功能定位

定时发布允许创作者提前编辑内容，并指定未来某个时间自动发布。

适合场景：


```text

  ↓

  ↓
```

```text
  ↓
优质内容被加精、置顶、推荐
  ↓
用户获得积分、经验、勋章
  ↓
参与任务、签到、活动
  ↓
平台通过搜索、推荐、运营活动持续提升活跃
  ↓
后台进行内容治理、圈子治理、话题运营、数据分析
```

# 19. 总结

V2 增强版的社区产品不再只是一个基础发帖评论系统，而是升级为一个完整的兴趣社区平台。

它的核心能力从原来的：

```text
内容发布
内容浏览
评论互动
审核治理
```

升级为：

```text
内容分类
兴趣圈子
话题聚合
搜索推荐
用户成长
活动运营
内容沉淀
社区治理
```

最终平台形态可以概括为：

```text
以内容为核心
以标签和话题做聚合
以圈子承载关系
以搜索推荐提升分发
以积分成长提升活跃
以活动运营制造增长
以后台治理保障社区质量
```
