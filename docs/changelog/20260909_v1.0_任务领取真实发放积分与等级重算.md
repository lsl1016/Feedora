# 任务领取真实发放积分与等级重算

## 1. 背景与目标

阶段二的成长任务体系中，`POST /growth/tasks/:taskId/claim` 一直是对接前端的占位实现：仅校验路径参数后恒返回 `{"claimed": true}`，不校验任务进度、不写积分流水、不发放积分；同时 `users.level` 字段没有任何写入路径，用户等级注册后恒为 1，等级名称映射（资深专家/活跃达人等）实际永远不会生效。

本次改动补齐这两处：任务 1（发布首篇帖子）与任务 2（参与评论）在进度达标后经积分流水真实发放奖励；所有积分发放路径在累加 `point_count` 的同一条 UPDATE 语句中重算 `level`，使等级随积分增长。

## 2. 代码改动

- 文件：`internal/service/growth_service.go`
  - 新增 `ClaimTask(userID, taskID)`：按任务 ID 取进度目标与奖励——任务 1 发布首篇帖子（目标 `post_count >= 1`，奖励 10 分）、任务 2 参与评论（目标 `comment_count >= 3`，奖励 3 分），进度达标后调用 `AddPointLog(userID, "task_claim", points, "task", taskID, "任务奖励："+title)` 发放。
  - 任务 3（每日签到）不走领取，返回 60003 提示通过签到接口完成；未知任务 ID 返回参数错误（400）。
  - 进度未达标返回 60001；`AddPointLog` 返回 false（`uk_user_action_biz` 唯一索引冲突）时返回 60002 已领取，同一任务对同一用户只发一次。
- 文件：`internal/api/growth_api.go`
  - `ClaimTask` 处理器从恒返回 `{"claimed": true}` 改为调用 `svc.ClaimTask` 并透传业务错误（`response.Fail`），成功时响应结构不变。
- 文件：`internal/repository/growth_repository.go`
  - `AddPointLog` 在累加 `point_count` 的同一条 `UpdateColumns` 中以 SQL 表达式重算 `level = GREATEST(1, FLOOR(point_count / 100) + 1)`：每 100 积分升 1 级，最低 1 级。签到、Worker 事件发放、任务领取全部经该函数，均触发等级重算。
- 文件：`pkg/errors/code.go`
  - 新增业务错误码：60001 `ErrTaskNotDone`（任务进度未达标，暂不能领取）、60002 `ErrTaskClaimed`（任务奖励已领取过）、60003 `ErrTaskClaimViaCheckIn`（该任务通过每日签到完成，无需领取）。

## 3. 影响范围

- 接口：
  - `POST /growth/tasks/:taskId/claim` 行为变更：进度未达标返回 60001、重复领取返回 60002、任务 3 返回 60003、非法任务 ID 返回 400；达标首次领取真实写入积分流水并累加积分。成功响应仍为 `{"claimed": true}`。
  - 其余 growth 接口（签到、任务列表、排行榜）无变化。
- 模块：
  - `user_point_logs` 新增 `action = "task_claim"`、`biz_type = "task"`、`biz_id = 任务ID` 的流水形态。
  - `users.level` 出现维护路径：任何积分发放都会重算等级；排行榜与用户信息中展示的等级、等级名称随之生效。
  - Worker 六类事件发放路径与签到路径的行为不变，但同样附带等级重算。
- 配置：
  - 不新增配置项、数据表或缓存键。奖励数值（任务 1 为 10 分、任务 2 为 3 分）为服务层硬编码。

## 5. 风险与兼容性

- 依赖占位行为（调任意 taskId 均返回成功）的调用方在升级后会开始收到 400/60001/60002/60003 业务错误，前端需处理这些错误码。
- 等级重算表达式依赖 MySQL 的 `GREATEST`/`FLOOR` 函数，与当前数据库绑定。
- 等级仅在积分发放时重算：存量用户的 `level` 保持历史值，直到下一次积分变动才会刷新；无独立的定时回填任务。
- 幂等依赖 `uk_user_action_biz(user_id, action, biz_type, biz_id)`，任务领取维度为 `(userID, "task_claim", "task", taskID)`；`AddPointLog` 中积分累加与等级重算的 UPDATE 执行错误被忽略，失败时流水已写入但计数字段可能未更新（与既有签到路径一致）。
