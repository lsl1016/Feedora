# 修复帖子计数双重递增与删帖不对称回减

## 1. 背景与目标

### 问题描述

- 已发布帖子创建成功后，作者 `users.post_count` 被递增两次（+2），删除时仅回减一次（-1），计数长期虚高。
- 删除已发布帖子只回减作者计数，`topics.post_count`、`circles.post_count`、`tags.use_count` 均不回减，四类关联计数只增不减。
- 草稿、定时帖在创建时同样递增 `users.post_count` 与 `circles.post_count`，未发布即占用计数。

### 根因分析

- `PostRepository.CreateWithRelations` 在事务内对 `users.post_count`、`circles.post_count` 无条件 +1；`PostService.Create` 在事务提交后又调用一次 `users.IncColumn(authorID, "post_count", 1)`，仓储层与 Service 层各加一次，形成双重递增。
- 原 `SoftDelete` 只负责置 `deleted` 状态与 GORM 软删，计数回减散落在 Service 层且仅覆盖 `users.post_count` 一项，与创建路径的递增清单不对称。
- 递增逻辑不区分帖子状态，`draft` / `scheduled` 帖在发布前即计入作者与圈子发帖数。

### 影响范围

- `users.post_count`、`circles.post_count` 随发布/删除循环持续虚高。
- `topics.post_count`、`tags.use_count` 在删帖后不复原，与实际关联帖子数偏离。

## 2. 代码改动

- 文件：`internal/repository/post_repository.go`
  - `CreateWithRelations`：`users.post_count + 1` 与 `circles.post_count + 1` 增加 `p.Status == model.PostPublished` 条件，草稿、定时帖不再递增这两项计数；`topics.post_count` 与 `tags.use_count` 维持原有无条件递增，不区分帖子状态。
  - 删除原 `SoftDelete`，新增 `SoftDeleteWithCounters`：在单个数据库事务内置 `status = deleted` 并执行 GORM 软删除；帖子原状态为 `published` 时对称回减 `users.post_count`、关联 `topics.post_count`、`circles.post_count`、`tags.use_count`，全部使用 `GREATEST(col - 1, 0)` 表达式防止计数为负；原状态非 `published` 时只置状态与软删，不回减计数。
- 文件：`internal/service/post_service.go`
  - `Create`：删除事务提交后 Service 层对 `users.IncColumn(authorID, "post_count", 1)` 的第二次调用，一次成功发布作者计数仅 +1。
  - `Delete`：改为调用 `SoftDeleteWithCounters`，不再手工回减作者计数。
  - `SetHidden`：取消隐藏分支发布事件时将裸字符串 `"PostUnhidden"` 改用常量 `event.PostUnhidden`。

## 3. 影响范围

- 接口：`POST /posts`、`DELETE /posts/:postId` 的计数维护行为变化，请求参数与响应结构不变；`PUT /posts/:postId/unhide` 发布的事件类型值不变（仍为 `PostUnhidden`），仅改用常量引用。
- 模块：post（计数维护逻辑）；user、circle、topic、tag 模块的冗余计数值走向随之修正。事件链路与消费者不受影响。
- 配置：不新增数据表、配置项或缓存。

## 4. 测试验证

- 命令：`go build ./...`、`go vet ./...`、`go test ./...`
- 结果：`go build ./...` 通过（exit 0）；`go vet ./...` 通过（exit 0）；`go test ./...` 结果 `ok github.com/feedora/backend/internal/api`，其余包无测试文件。集成路径未在真实 MySQL/Redis/Kafka 环境回归，以编译与现有单测验证。

## 5. 风险与兼容性

- 已发布帖的作者 `post_count` 由 +2 变为 +1，新产生的计数准确；存量虚高数据不在本次改动内自动修正。
- 删除已发布帖现在同时回减用户、话题、圈子、标签四类计数，均以 0 为下限，不会出现负数。
- 草稿、定时帖创建不再递增作者与圈子计数；当前代码不存在草稿/定时帖转为已发布后补增计数的路径。
- `topics.post_count`、`tags.use_count` 创建侧仍为无条件递增，与修改前口径一致，仅补齐删除侧对称回减。
