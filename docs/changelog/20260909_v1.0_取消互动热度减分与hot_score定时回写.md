# 取消互动热度减分与 hot_score 定时回写

## 1. 背景与目标

两个问题：

- 榜单 ZSet 只加不减：`PostUnliked` / `PostUnfavorited` 事件到达 `handleRank` 后落入 default 分支被忽略，取消点赞、取消收藏后帖子热度维持原值，榜单与实际互动状态脱节。
- `posts.hot_score` 无业务写入路径：该列仅 `cmd/seed` 种子数据赋值，线上恒为 0。帖子列表 `sort=hot` 与热榜 DB 回退排序声明按 `hot_score DESC`，实际由 `like_count`、`created_at` 决定。

目标：取消互动对榜单执行负增量；Redis ZSet 累计热度定期落库，使 `hot_score` 有业务回写路径。

## 2. 代码改动

- 文件：`internal/worker/handlers.go`
  - `handleRank` 新增两个 case：`PostUnliked` 热度 -3、`PostUnfavorited` 热度 -4，与点赞 +3、收藏 +4 对称。负增量经 `ZIncr` 写入 `today` / `week` / `all` 三个 timeRange 的 post 榜 ZSet；只减榜单热度，不追回 growth 模块已发放的积分。
- 文件：`internal/worker/runner.go`
  - `Run` 新增 goroutine `hotScoreLoop`：Redis 未启用时直接返回；否则每 5 分钟调用一次 `flushHotScore`。
  - `flushHotScore`：取 `rank:post:all` ZSet Top 200，逐条将 member 解析为帖子 ID 后 `UpdateColumn("hot_score", ...)` 写回 `posts` 表（不更新 `updated_at`），并记录回写条数日志。

## 3. 影响范围

- 接口：无新增或变更接口。
- 模块：rank（ZSet 计分规则新增负增量、新增定时回写任务）；post（`posts.hot_score` 从仅种子数据写入变为每 5 分钟业务回写，帖子 hot feed 排序与热榜 DB 回退排序随之生效）。
- 配置：不新增配置项；回写周期 5 分钟与 Top 200 为 `internal/worker/runner.go` 中的硬编码值。未启用 Redis 时 `hotScoreLoop` 跳过，`hot_score` 仍无业务写入路径。

## 4. 测试验证

- 命令：`go build ./...`、`go vet ./...`、`go test ./...`
- 结果：`go build ./...` 通过（exit 0）；`go vet ./...` 通过（exit 0）；`go test ./...` 结果 `ok github.com/feedora/backend/internal/api`，其余包无测试文件。集成路径未在真实 MySQL/Redis/Kafka 环境回归，以编译与现有单测验证。

## 5. 风险与兼容性

- 取消互动多于互动时 ZSet 分数可为负，member 不会因负分被移出 ZSet，仍出现在榜单候选中。
- `hot_score` 回写仅覆盖 `rank:post:all` Top 200：未进 Top 200 的帖子不回写，保持原值（默认 0 或种子值）。
- DB 中 `hot_score` 与 ZSet 最多相差一个回写周期（5 分钟）；未启用 Redis 的部署 `hot_score` 仍为静态值，行为与改动前一致。
- 积分与热度解耦：取消点赞 / 取消收藏不回收 growth 模块已发放积分，`users.point_count` 与榜单热度不要求一致。
- `UpdateColumn` 不触发 GORM 钩子、不刷新 `updated_at`，以 `updated_at` 判断帖子活跃度的逻辑不受影响。
