# 话题索引增量同步

## 1. 背景与目标

ES 话题索引（`feedora_topics`）此前只有 Worker 启动时全量重建一条写入路径：后台创建、编辑话题不发布任何事件，索引中的话题数据在下一次 Worker 重启前保持旧值——新建话题搜不到，改名后索引仍返回旧名称。

目标：为话题建立与帖子 / 用户 / 圈子一致的增量同步链路，后台创建 / 更新话题后异步重建索引文档。

## 2. 代码改动

- 文件：`internal/event/event_type.go`
  - 新增事件类型常量 `TopicCreated` / `TopicUpdated`。
- 文件：`internal/event/topic.go`
  - 新增第 6 个 Kafka topic 常量 `TopicTopic = "topic.events"`。
- 文件：`internal/worker/runner.go`
  - `topicsWithPrefix` 订阅列表与 `EnsureTopics` 预建列表加入 `topic.events`（实际名 `{kafka.topicPrefix}.topic.events`，默认 `feedora.topic.events`）。
- 文件：`internal/worker/handlers.go`
  - `handleSearch` 新增 case `TopicCreated` / `TopicUpdated`：经 `idem.Claim(eventID, "search")` 后按 `AggregateID` 回查话题，存在时调用既有 `indexTopic` 重建文档，不存在时跳过。
- 文件：`internal/service/admin_service.go`
  - `CreateTopic` / `UpdateTopic` 写库成功后向 `topic.events` 发布 `TopicCreated` / `TopicUpdated` 事件（admin 服务注入 producer 的装配细节由 admin 模块 changelog 覆盖）。

## 3. 影响范围

- 接口：无接口变更。`/search`（`type=topic` / `all`）与话题相关搜索结果的时效性变化：后台创建 / 更新的话题经 Outbox + Kafka 异步进入索引。
- 模块：search（索引同步新增两类事件、新增订阅 topic）；admin（`CreateTopic` / `UpdateTopic` 成功后发布话题事件）；event（新增常量）。
- 配置：不新增配置项。新增 Kafka topic `feedora.topic.events` 由 Worker 启动时 `EnsureTopics` 预建。话题删除仍无事件，已删话题文档保留在索引中直到下次全量重建。

## 4. 测试验证

- 命令：`go build ./...`、`go vet ./...`、`go test ./...`
- 结果：`go build ./...` 通过（exit 0）；`go vet ./...` 通过（exit 0）；`go test ./...` 结果 `ok github.com/feedora/backend/internal/api`，其余包无测试文件。集成路径未在真实 MySQL/Redis/Kafka 环境回归，以编译与现有单测验证。

## 5. 风险与兼容性

- 索引同步为异步链路（Outbox 批量投递 + 消费），后台保存后到索引可搜存在秒级延迟。
- `kafka.enabled=false` 时生产者为 Noop、Worker 不运行，话题索引回到仅启动全量重建状态，搜索接口仍可查询既有索引内容。
- 事件发布位于写库成功之后、接口返回之前，Outbox 写入失败不影响接口结果，该次变更不同步索引。
- 话题删除无事件：已删话题的索引文档依赖下次 Worker 重启全量重建收敛；已禁用（disabled）话题的更新事件仍会重建文档，查询侧按 `status.keyword=enabled` 过滤。
