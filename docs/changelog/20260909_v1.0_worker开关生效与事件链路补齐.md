# worker 开关生效与事件链路补齐

## 1. 背景与目标

基础设施层存在一批"配置了但不生效"与"常量缺失"的欠账：`worker.enabled` 配置键无任何代码读取，Worker 是否运行仅由 `kafka.enabled` 决定；`oss.type` 同样无人消费，配置为 minio/aliyun 时静默落回本地存储；`PostUnhidden` 事件在发布处与消费处均为字符串字面量，无常量定义；counter 子包声明的"Redis 计数回写 MySQL"职责未实现，未启用 Redis 的部署读不到热门分。此外 admin 模块新增的话题/帖子状态事件需要对应 topic 与消费方。

本次改动使两个配置键真实生效，补齐事件常量与 topic 订阅，并在 Runner 内落地 counter（hotScoreLoop）与 stat（handleStat）两项职责。

## 2. 代码改动

- 文件：`cmd/worker/main.go`
  - 配置加载后新增 `worker.enabled` 检查：false 时记录告警并退出。该配置键此前无代码读取；Worker 退出条件变为 `worker.enabled` 与 `kafka.enabled` 均需为 true。
- 文件：`internal/app/app.go`
  - `oss.type` 新增 switch 分支：空或 `local` 初始化 `LocalStorage`，其他值启动直接报错退出（minio/aliyun 实现未落地，显式失败优于静默降级；详见 file 模块 changelog）。
  - `NewAdminService` / `NewNotificationService` 装配签名变更：前者注入 `event.Producer`（见 admin 模块 changelog），后者注入 `cache.Cache`（未读数 cache-aside 依赖）。
- 文件：`internal/event/event_type.go`
  - 事件常量新增 `PostUnhidden`、`PostUnfavorited`、`TopicCreated`、`TopicUpdated`，常量总数 13 → 17；`PostUnhidden` 结束发布处与消费处的字面量用法。
- 文件：`internal/event/topic.go`
  - 新增第 6 个 Topic 常量 `TopicTopic = "topic.events"`（实际 topic `feedora.topic.events`），承载话题增量索引事件。
- 文件：`internal/worker/runner.go`
  - 订阅列表 `topicsWithPrefix` 与 `Run` 内 `EnsureTopics` 加入 `TopicTopic`，消费与预创建均为 6 个 topic。
  - `Run` 新增 `hotScoreLoop` goroutine：Redis 启用时每 5 分钟执行 `flushHotScore`，取 `rank:post:all` ZSet Top 200 写回 `posts.hot_score`，使未启用 Redis 的部署也能按 `hot_score` 排序；counter 职责落地为 Runner 内定时器。
- 文件：`internal/worker/handlers.go`
  - `handle()` 分发链新增第 5 个处理器 `handleStat`（幂等名 `stat`）：消费 `PostCreated` / `PostDeleted` 后调用 `TopicRepository.RecomputeParticipantCountsByPost` 按帖重算所属话题参与人数。
  - `notify()` 未读 Key 操作由 `Incr` 改为 `Del`：通知落库后失效 `notify:unread:{userID}` 缓存，未读数读取改为 cache-aside（未命中回源 DB COUNT 并带 TTL 写回，配合 `Cache.GetIntOK`）。
- 文件：`internal/cache/cache.go`
  - 新增 `GetIntOK`：读取整型计数并区分"未命中"（Key 不存在或不可解析时 ok 为 false），支撑未读数回源逻辑。
- 文件：`pkg/errors/code.go`
  - 新增 60001-60003 任务领取业务错误码（改动事实归 growth 模块 changelog 记录，此处仅登记文件变更）。

## 3. 影响范围

- 接口：
  - 无直接对外接口变化；API 进程的未读数接口行为不变（读路径实现调整）。
- 模块：
  - Worker 消费订阅从 5 个 topic 变为 6 个（新增 `feedora.topic.events`）；事件分发从 4 个处理器变为 5 个。
  - `posts.hot_score` 出现维护路径（每 5 分钟批量回写 Top 200），rank 模块 Redis 未启用时的 DB 回退排序有了数据来源。
  - `topics.participant_count` 由 Worker 在帖子创建/删除后重算（stat 职责落地）。
  - notification 模块未读数从"只查 DB"变为 Redis cache-aside；`NewNotificationService` 构造签名变更。
  - `internal/app/app.go` 装配对 `oss.type` 非法值开始报错。
- 配置：
  - `worker.enabled` 现已生效：false 时 Worker 进程启动即退出。
  - `oss.type` 现已生效：空或 `local` 用本地存储，其他值 API 进程启动失败。
  - 不新增配置键、数据表或缓存键。

- 结果：通过（exit 0）。
- 命令：`go vet ./...`
- 结果：通过（exit 0）。
- 命令：`go test ./...`

## 5. 风险与兼容性

- `worker.enabled=false` 现在会真的停掉 Worker：此前依赖"该键不生效、Worker 始终由 kafka.enabled 控制"的部署在升级后行为改变（outbox 投递与全部异步消费停止，事件积压在 `event_outbox`）。
- `oss.type` 配置为 `minio` / `aliyun` 的存量部署升级后 API 进程启动失败，需先改回 `local`。
- 未读数从 Incr 计数改为失效回源：通知写入高频时未读数读取会周期性回源 DB（有 TTL 缓存兜底），且缓存与 DB 之间存在秒级不一致窗口。
- `hotScoreLoop` 每 5 分钟最多产生 200 条单行 UPDATE；`flushHotScore` 的更新错误逐条忽略。
- 消费循环仍为单 reader 串行处理，新增 stat 处理器使每条事件的串行处理时长增加。
