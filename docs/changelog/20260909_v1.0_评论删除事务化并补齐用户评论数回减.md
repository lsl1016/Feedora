# 评论删除事务化并补齐用户评论数回减

## 1. 背景与目标

### 问题描述

- 删除评论的三条语句（置 `status = deleted`、GORM 软删写 `deleted_at`、`posts.comment_count` 回减）不在同一事务内执行，中途失败会产生状态与计数不一致。
- 删除评论不回减 `users.comment_count`，而创建评论时 `CreateWithCounters` 同时递增 `posts.comment_count` 与 `users.comment_count`（+1/+1），删除侧只回减帖子一侧，用户累计评论数只增不减。

### 根因分析

- 原 `SoftDelete` 以三条相互独立的语句依次执行，未包裹数据库事务。
- 回减清单缺少 `users.comment_count` 一项，与创建路径的递增清单不对称。

### 影响范围

- `users.comment_count` 随评论删除不断偏离真实值，只增不减。
- 非事务路径下部分语句失败时，`comments` 状态、`deleted_at` 与 `posts.comment_count` 出现中间态不一致。

## 2. 代码改动

- 文件：`internal/repository/comment_repository.go`
  - 原 `SoftDelete` 替换为 `DeleteWithCounters`：原三条非事务语句改为在单个数据库事务内执行，并补充 `users.comment_count` 回减；`posts.comment_count` 与 `users.comment_count` 均使用 `GREATEST(col - 1, 0)` 表达式防止计数为负，与创建时 `CreateWithCounters` 的 +1/+1 对称。
- 文件：`internal/service/comment_service.go`
  - `Delete` 的仓储层调用点由 `SoftDelete` 改为 `DeleteWithCounters`。

## 3. 影响范围

- 接口：`DELETE /comments/:commentId`（作者本人或 admin 角色）的计数维护行为变化，请求参数与响应结构不变。
- 模块：comment（删除路径）；`posts.comment_count`、`users.comment_count` 的数值走向受影响，涉及 user、post 模块的冗余计数字段。
- 配置：不新增数据表、配置项或缓存。

## 4. 测试验证

- 命令：`go build ./...`、`go vet ./...`、`go test ./...`
- 结果：`go build ./...` 通过（exit 0）；`go vet ./...` 通过（exit 0）；`go test ./...` 结果 `ok github.com/feedora/backend/internal/api`，其余包无测试文件。集成路径未在真实 MySQL/Redis/Kafka 环境回归，以编译与现有单测验证。

## 5. 风险与兼容性

- 删除评论后 `users.comment_count` 对称回减，新产生的计数准确；存量只增不减的历史数据不在本次改动内自动修正。
- 回减以 0 为下限，重复删除或异常数据不会使计数为负。
- 删除根评论仍不级联删除其子回复，`posts.comment_count` 仍仅回减 1，与修改前行为一致。
- 删除评论仍不发布事件，下游通知与热度榜单不回退，与修改前行为一致。
