# 新增用户封禁与帖子上下架接口

## 1. 背景与目标

后台管理模块此前以查询能力为主，仅有的写操作是标签与话题管理。用户封禁与帖子上下架两类治理动作缺失：`users.status` 的 `banned` 值虽被登录链路消费（`AuthService` 登录时校验并返回 10003），但后台没有任何接口能把用户置为 banned；帖子状态同样只能只读过滤，无法下架或恢复。`operation_logs` 表只有读取路径，正常运转下恒为空表。

本次改动新增两个写接口，使后台具备用户封禁与帖子上下架能力，操作落操作日志，帖子状态变更后发 Kafka 事件供 Worker 同步 ES 索引；同时补上话题创建/更新后的增量索引事件。

## 2. 代码改动

- 文件：`internal/router/admin_router.go`
  - 新增路由 `PUT /admin/users/:userId/status` 与 `PUT /admin/posts/:postId/status`，注册在与既有 admin 路由相同的分组（`authMW + adminMW`，先认证后管理员鉴权）。
- 文件：`internal/api/admin_api.go`
  - 新增 `UserStatus` / `PostStatus` 处理器，Swagger 注释齐全；路径参数复用 `dto.UserIDURI` / `dto.PostIDURI`，请求体分别绑定 `AdminUserStatusRequest` / `AdminPostStatusRequest`，成功返回 `{"updated": true}`，业务错误透传。
- 文件：`internal/dto/admin_dto.go`
  - 新增 `AdminUserStatusRequest`（`status` 必填，取值 `normal` / `banned`）与 `AdminPostStatusRequest`（`status` 必填，取值 `published` / `hidden` / `takedown`）。
- 文件：`internal/service/admin_service.go`
  - 构造函数 `NewAdminService` 签名变更：注入 `event.Producer`（新增末位参数，`app.go` 装配同步调整）。
  - 新增 `SetUserStatus(adminID, userID, status)`：校验状态枚举（仅 `model.UserNormal` / `model.UserBanned`）与用户存在性（不存在返回 404），更新后写操作日志。
  - 新增 `SetPostStatus(adminID, postID, status)`：校验状态枚举（仅 `model.PostPublished` / `PostHidden` / `PostTakedown`）与帖子存在性（不存在返回 20001），更新后写操作日志，并按目标状态发事件到 `TopicPost` 供 ES 索引同步：`published` → `PostUnhidden`、`hidden` → `PostHidden`、`takedown` → `PostUpdated`；事件 `user_id` 为管理员 ID。
  - 新增私有 `log()`：写入 `operation_logs`，`AdminName` 回查管理员昵称（查不到为空串），`action` 为 `update_user_status` / `update_post_status`。
  - `CreateTopic` / `UpdateTopic` 落库成功后向 `TopicTopic` 发 `TopicCreated` / `TopicUpdated` 事件（话题搜索增量索引，`user_id` 为 0）。
- 文件：`internal/repository/admin_repository.go`
  - 新增 `GetPostByID`（不存在返回 nil）、`UpdatePostStatus`、`UpdateUserStatus`（按 ID 单列更新 status）、`AddLog`（写入前设置 `created_at`，写入错误忽略）。

## 3. 影响范围

- 接口：
  - 新增 `PUT /api/v1/admin/users/:userId/status`（body `{"status": "normal"|"banned"}`）。
  - 新增 `PUT /api/v1/admin/posts/:postId/status`（body `{"status": "published"|"hidden"|"takedown"}`）。
  - 既有接口契约不变；话题创建/更新接口新增事件发布副作用，响应结构不变。
- 模块：
  - admin 从只读为主变为具备用户与内容治理写能力；`operation_logs` 出现写入路径，日志列表接口开始有真实数据。
  - 用户封禁与 auth 模块联动：被封禁用户登录被拦截（10003）；后台用户列表固定过滤 `status <> 'banned'`，被封禁用户在列表中不可见。
  - 帖子状态变更经 Kafka 事件驱动 Worker 的 `handleSearch` 重建 ES 索引；话题增删改经 `feedora.topic.events` 维护话题索引。
  - `NewAdminService` 构造签名变更，调用方 `internal/app/app.go` 同步调整。
- 配置：
  - 不新增配置项。事件发布依赖 `kafka.enabled`：关闭时生产者为 Noop 实现，仅打印日志不发事件。

## 5. 风险与兼容性

- 封禁对已签发的 JWT 不生效：状态校验仅在登录时进行，token 有效期内被封禁用户仍可携带旧 token 访问需认证接口。
- `SetUserStatus` 不限制目标账号角色：可将管理员账号置为 banned，被封禁的管理员在 token 过期后无法重新登录。
- 被封禁用户从后台列表消失，解禁操作需要已知其 userId 直接调用接口，列表页无法检索到该用户。
- `takedown` 状态复用 `PostUpdated` 事件，ES 侧按帖子当前状态重建索引文档。
- 状态枚举外的值返回 400；帖子/用户不存在分别返回 20001 / 404。`AddLog` 失败被静默忽略，状态更新成功但可能缺操作日志。
- 话题创建/更新发事件使 `TopicTopic` topic 产生流量，依赖 Worker 订阅该 topic（见 infrastructure 模块本次改动），Worker 未升级到订阅 `topic.events` 的版本时事件只投递不被消费。
