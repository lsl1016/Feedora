# Feedora 后端四类遗留问题修复计划

用户已确认：worker **不重构**（新逻辑继续加在 handlers.go，八个占位目录保持现状）；PostUnliked/PostUnfavorited **只减热度不追积分**；文档**每模块一篇 changelog** + 系统文档升 v1.1。

## 批次 A：计数漂移（问题 1）

1. **post_count 双重递增**（`internal/repository/post_repository.go` + `internal/service/post_service.go`）
   - `CreateWithRelations` 事务内所有计数递增（users.post_count、topics.post_count、circles.post_count）加 `p.Status == model.PostPublished` 条件——顺带修掉草稿帖也涨计数的暗病
   - 删除 Service 层 `Create` 里的第二次 `s.users.IncColumn(authorID, "post_count", 1)`
2. **删帖只 -1 且不对称回减**：新增 `PostRepository.SoftDeleteWithCounters(p)`——事务内：置 deleted + 软删 + 原状态为 published 时 `users.post_count`、关联 `topics.post_count`、`circles.post_count`、`tags.use_count` 各 -1（全部 GREATEST(col-?,0) 防负）；`PostService.Delete` 改调它，删掉原来的裸 `SoftDelete` + 手工 -1
3. **评论删除非事务且漏减用户计数**：`CommentRepository.SoftDelete` 改为 `DeleteWithCounters`——事务内三条语句 + 补 `users.comment_count` -1（GREATEST 防负）；`comment_service.go` 调用点同步更新

## 批次 B：写而不读 / 读而不写（问题 2）

4. **未读数 Redis 死数据** → 改为标准 cache-aside：
   - `Cache` 补 `Del` / 带 TTL 的 SetInt（缺才加，`internal/cache/cache.go`）
   - `NotificationService.UnreadCount`：GET 命中直接返回；miss 时 DB COUNT 后 SETEX(10min)
   - `MarkRead` / `MarkAllRead` 成功后 DEL key；worker `notify()` 落库后由 `Incr` 改为 DEL（失效而非累加，永不漂移）
   - `NewNotificationService` 注入 cache，`app.go` 装配更新
5. **topics.participant_count 无写入**：新增 `TopicRepository.RecomputeParticipantCounts(ids)`（UPDATE 子查询 COUNT DISTINCT author_id，排除已删帖）；`handlers.go` 新增 `handleStat`：PostCreated/PostDeleted 事件按 AggregateID 反查 post_topics 后触发重算（幂等，天然覆盖删除场景）
6. **posts.hot_score 无业务写入**：`runner.go` 新增 `hotScoreLoop` 定时器（5 分钟）——`ZTop(rank:post:all)` 批量写回 `posts.hot_score`，即原设计注释中"counter：Redis 计数回写 MySQL"的职责，落在 runner 内不新建包
7. **oss.type 配而不读**：`app.go` 存储实例化改为 switch——`""`/`local` → LocalStorage，`minio`/`aliyun` → 启动即报错"未实现"（fail-fast，不再静默降级）
8. **worker.enabled 配而不读**：`cmd/worker/main.go` 加载配置后 `if !cfg.Worker.Enabled` 则告警退出

## 批次 C：占位实现（问题 3）

9. **growth 任务领取占位**：`GrowthService` 新增 `ClaimTask(userID, taskID)`——静态任务定义补 Points 字段；进度达标才发放，`AddPointLog(userID, "task_claim", points, "task", taskID, …)`（唯一索引天然幂等，重复领取返回已领取）；未达标返回业务错误；`growth_api.go ClaimTask` 改走 service
10. **用户等级恒为 1**：`growth_repository.AddPointLog` 更新 `point_count` 的同处再 `UpdateColumn level = GREATEST(1, FLOOR(point_count/100)+1)`——单一写入点，读路径全部自动正确
11. **admin 缺写接口**（复用既有常量与事件，不新造语义）：
    - `PUT /admin/users/:userId/status`（normal/banned，登录拦截 `auth_service.go:82` 已消费 banned）
    - `PUT /admin/posts/:postId/status`（published/hidden/takedown），变更后发 `PostHidden`/`PostUnhidden`/`PostUpdated` 事件供 ES 同步
    - 两接口写 `operation_logs`（`AdminRepository` 新增 `AddLog`，顺带激活这张只读表）
    - `AdminService` 注入 producer；`AdminRepository` 新增 `GetPostByID`/`UpdatePostStatus`/`UpdateUserStatus`
