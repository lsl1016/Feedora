请生成链路追踪设计文档。

内容包括：

1. 链路追踪目标

2. Trace 上下文传播规范

HTTP 请求头使用 W3C Trace Context：

- traceparent
- tracestate

同时兼容：

- X-Trace-Id
- X-Request-Id

3. Gin 中间件设计

需要说明：

- 如果请求头已有 traceparent，则继续使用
- 如果没有，则生成新的 traceId
- traceId 写入 gin.Context
- traceId 写入响应头
- traceId 写入日志字段

4. Service 层传递规范

所有 service 方法必须接收 context.Context：

func (s *PostService) CreatePost(ctx context.Context, userID int64, req dto.CreatePostRequest) error

禁止 service 层使用 gin.Context。

5. Repository 层传递规范

所有 GORM 查询必须使用：

6. Kafka 链路传播

生产 Kafka 事件时，需要把 traceId 放入：

- Kafka Header
- Event.TraceID 字段

消费 Kafka 事件时：

- 从 Header 或 Event.TraceID 恢复 trace
- 新建 Consumer Span
- 日志中记录 eventId、eventType、traceId

7. Outbox 链路追踪

Outbox 表中需要保存 trace_id 字段。

如果当前表没有，请给出新增字段 SQL：
