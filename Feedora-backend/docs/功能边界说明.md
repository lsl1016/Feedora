# Feedora 已实现功能边界说明

> 本文档基于当前代码实际实现（后端路由 + 前端接口映射）整理，用于界定"已实现 / 未实现"的范围。
> 生成日期：2026-07-08。以后端 `internal/router` 路由与前端 `src/api/index.ts` 映射为准。

## 一、总体结构

| 部分 | 技术栈 | 说明 |
| --- | --- | --- |
| 后端 | Go + Gin + GORM | 提供 `/api/v1` REST 接口，共 14 个业务模块、约 64 个接口 |
| 前端 | React + TypeScript + Vite | 全部走后端真实接口，无本地 mock |
| 可执行程序 | `cmd/api`、`cmd/worker`、`cmd/migrate`、`cmd/seed` | API 服务、异步 worker、数据库迁移、初始化种子数据 |

### 可选依赖（未启用时自动降级，不影响启动）

- **Redis**：缓存，`redis.enabled=false` 时走空实现。
- **Elasticsearch**：搜索，`elasticsearch.enabled=false` 时按数据库回退。
- **Kafka**：事件投递，`kafka.enabled=false` 时用 Noop 生产者（仅打印日志）。
- 文件存储：本地目录模拟 OSS（`/static` 对外提供访问）。

### 非功能特性（已实现）

- JWT 鉴权：登录颁发 token；`OptionalAuth` 全局识别登录态，`Auth`/`Admin` 中间件保护受限接口。
- 登出为无状态：后端不维护会话，由前端清除 token。
- 可观测性：Prometheus 指标（`/metrics`）、链路追踪、结构化日志。
- 接口文档：Swagger，访问 `/swagger/index.html`，由 `swag init` 生成。
- 统一响应体 `{code, message, data, traceId, timestamp}` 与统一分页结构。

## 四、功能边界（未实现 / 前端占位，无后端支撑）

以下前端页面或能力**目前没有对应后端接口**，属于占位或规划中，尚不可端到端使用：

- **关注体系**：关注/取关用户、粉丝/关注列表。前端有「关注中心」页面（`following/FollowingCenterPage`），但后端无 `follow` 相关接口，前端 `api` 也未映射。
- **AI 工作台（workspace）**：AI 聊天、知识库、笔记、模型配置等页面（`pages/workspace/*`、`components/ai/*`）均为前端页面，后端无任何接口。
- **活动中心**：`pages/activity/*`（活动中心、活动详情），无后端接口。
- **公告**：`pages/announcement/*`，无后端接口。

### 其它边界说明

- **标签/话题的创建与编辑**仅在后台管理（管理员）开放，普通用户端只读。
- **文件上传**仅返回可访问 URL，使用本地存储模拟 OSS，非生产级对象存储。
- **搜索**能力依赖 Elasticsearch，未启用 ES 时按数据库回退，结果与排序可能与全文检索有差异。
- 部分后台接口（如更新话题、圈子成员角色/禁言）请求体为内联结构，未抽成命名 DTO，Swagger 文档中不展示请求体字段结构。

## 五、结论

已形成一个可端到端运行的社区内容平台核心：**账号、内容（帖/评/圈/标签/话题）、互动、搜索、榜单、成长、通知、文件、后台管理**均具备真实后端接口并被前端调用。

尚未打通的边界主要集中在 **关注体系、AI 工作台、活动、公告** 四块——这些是后续需要补齐后端接口才能落地的功能。
